## Реальная API-проверка

Из `backend`:

```powershell
node --env-file=.env scripts/check-tariff-release.cjs --apply
```

Скрипт ограничен loopback и development, использует текущую локальную
конфигурацию без вывода секретов. Требуется синхронизированный QA_AVIA_SYNC
из сценария [Авия → PMS](tariff-avia-sync-local.md). Остальные записи
создаются на время проверки. Обычный запуск без `--apply` не разрешён.

Через настоящие HTTP-обработчики проверены:

1. FRONT_DESK/CHANNEL_MANAGER читают тарифы и цены; FRONT_DESK получает 403
   на изменения; CHANNEL_MANAGER читает категории тарифов без `room.read`.
2. Создание и изменение с корпоративной основой возвращают 409.
3. Очистка описания и основы сохраняет `null`.
4. Одинаковые условия договоров 279/513 допустимы; повтор 279 с пробелами — 409.
5. Две ночи 19–21.11 для двух гостей дают 5 600 + 6 100 = 11 700 ₽,
   ставки НДС — 0% и 22%, `vatMixed: true`.
6. Стоп-продажи на вторую ночь сразу убирает предложение и возвращает 409
   при попытке брони, даже после предварительного запроса доступности.
7. Снятие ограничения сразу возвращает предложение.
8. Успешная бронь сохраняет полную сумму 11 700 ₽.

После проверки бронь отменена штатным API, временные тарифы и ограничения
удалены. Тестовая комната архивируется, учётка отключается; история проверки
сохраняется. Скрипт проверяет ответы очистки и не считает её ошибку успехом.
