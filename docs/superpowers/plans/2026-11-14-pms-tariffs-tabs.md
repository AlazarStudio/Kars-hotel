# PMS tariffs page tabs implementation plan

**Цель:** разделить тарифы гостиницы и реестр договоров двумя верхними
вкладками, сохранив состояние и прямые переходы. Решение Мусы утверждено;
повторное согласование дизайна не требуется. Astra планирует/проверяет,
Sol реализует, корневой агент проверяет локальный браузер.

**Границы:** `C:/dev/Kars-hotel`, `codex/mussa`, без коммита, новых worktree,
изменений backend/API/БД/ценовых правил. Сохранить существующие правки.
Исполнителю запрещены браузер, вход и пароли. Запуск сервисов не требуется.

**Архитектура:** обе панели сохраняются в дереве React, неактивная скрывается
через `hidden`. Заголовок и вкладки находятся в `.root` над единственной
вертикальной областью прокрутки `.contentScroll`. Мастер расположен вне
этой области. Оболочка `HotelPMS` уже ограничивает переполнение.

## 1. Верхние вкладки и сохранение состояния

- [x] Добавить `activeSection: 'plans' | 'contracts'` в Tariffs, по умолчанию
  `plans`. Общие queries, ошибки и мастер оставить на уровне Tariffs.
- [x] Вынести только содержимое двух разделов в стабильные sibling panels;
  не условно монтировать их по activeSection и не менять key при переключении.
  Так сохранятся selectedPlanId, текущий PlanPanel и его ContractPricesTab /
  ContractCalendar / RateCalendar. Не переделывать внутреннее ценообразование.
- [x] Два верхних tab со счётчиками `plans.length` / `contracts.length`;
  корректные tablist/tab/tabpanel, aria-selected/controls/labelledby,
  roving tabindex, стрелки и Home/End, видимый focus. Hidden-панель не участвует
  в раскладке и клавиатурном обходе. Верхний уровень отличается от subTabs.
- [x] Заголовок и верхняя навигация остаются видны над `.contentScroll`.
  Обе панели и сообщение об ошибке находятся внутри области прокрутки.
  «Новый тариф» находится рядом с `tablist` и виден только в разделе
  «Тарифы» при наличии `rate.update`. На узком экране кнопка занимает
  всю строку под вкладками.
  Обновить пустые состояния: убрать «в списке ниже», дать переход в договоры;
  contracts-panel доступна и при нуле договоров с объяснением синхронизации.
- [x] Сохранять `scrollTop` области `.contentScroll` отдельно для каждого
  раздела и восстанавливать после обновления DOM (`useLayoutEffect`).
  При прямом переходе передавать фокус цели и прокручивать к ней с отступом
  12 px от верха области, если длина содержимого позволяет.

## 2. Реестр и прямые переходы

- [x] OperatorContractPrices сохраняет search/shownSlice и управляемое
  раскрытие по ключу `partnerId + нормализованный number`. Пользовательское
  закрытие details не отменяется refetch; новый основной/единственный договор
  получает прежнее начальное раскрытие, без перезаписи выбранного состояния.
- [x] PlanPanel получает callback «Открыть договор» только при найденном
  партнёре+номере; у своего тарифа ссылки нет. Tariffs переключает раздел,
  задаёт целевой contract key, реестр раскрывает и фокусирует соответствующий
  summary. При несовпадении с поиском дополнительно показать эту цель и
  коротко объяснить, что поиск сохранён; при вводе поиска снять исключение.
- [x] Существующий `planForSlice` использовать без ослабления сравнения
  партнёра/договора/юрлица/АК/вида/питания. Вместо одной статичной пометки
  связанного тарифа дать подписанное действие «Открыть тариф», которое
  выбирает именно найденный id и показывает его PlanPanel. Не выбирать
  тариф по одному номеру договора. Переходы чтения не закрывать rate.update.
- [x] По успешному завершению handleSave выбрать возвращённый/сохранённый id
  и раздел plans. Промежуточное создание собственного тарифа перед шагом цен
  не считать завершением. При ошибке/отмене не переключать вкладку и не
  сбрасывать search, раскрытие или предпросмотр исходного договора.

## 3. Регрессии до/вместе с реализацией

- [x] Адаптировать helpers существующих UI-тестов: искать действия только
  внутри видимой панели/диалога; тесты реестра сначала открывают contracts.
  Скрытый mounted DOM не должен давать ложноположительные assertions.
- [x] Проверить названия/счётчики, пустые состояния, клавиатурную навигацию,
  отсутствие «Новый тариф» в contracts; rate.read сохраняет переходы/просмотр,
  rate.update по-прежнему нужен для создания/изменений.
- [x] Выбрать тариф, период ДС или календарь (30 дней, 2 гостя, сдвиг дат),
  уйти в contracts и вернуться: выбор и значения прежние. Аналогично search,
  раскрытие/закрытие details и предпросмотр после обратного переключения
  и фонового обновления. Проверить отдельные scrollTop и один scroll-root.
- [x] «Открыть договор» выбирает правильного партнёра при одинаковых номерах,
  показывает цель при несовпадающем сохранённом поиске; «Открыть тариф»
  выбирает правильный срез. Несуществующий договор не даёт ложной ссылки.
- [x] Создание из договора передаёт исходные IDs, после успеха виден созданный
  тариф. Отмена через guard и ошибка сохранения оставляют исходный раздел;
  черновик, шаг и введённые поля переживают фоновые обновления. Прежние
  тесты справочника `contractDirectoryRefresh.test.mjs` остаются зелёными.
